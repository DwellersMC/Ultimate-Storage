# UltStorage 模组文档

**UltStorage** 是一个 Minecraft 纯服务端 Fabric 模组，把被绑定的容器汇聚成**整个存档共用的一个物品存储**。在默认模式下，送进被绑定容器的物品会被抽进服务端存储里，所有玩家都能通过用原版容器封包发送的存储界面浏览与取出物品。

存储属于存档而不是某个名字：一个存档只有**一个**存储，它的输入就是被绑定到它上面的容器，同一个存储可以在任意维度被投料和打开。

See the English document [here](./README.md).

---

## 功能

- **每个存档一个共享存储**，任意维度都可访问
- 看着容器即可绑定（`/ults bind`），可带备注
- 一次绑定一整片区域（`/ults bindarea`），只扫描已加载的区块
- 存储界面按运行时发现的创造模式标签分类，模组物品自动出现
- 按玩家保存的界面状态：分类、分类页、物品页、物品 ID 过滤与物品显示方式
- 取出界面提供散装模式与整盒模式（潜影盒）
- 按玩家独立的高亮（`/ults show` 与 `/ults hide`）
- 被绑定的方块**受保护**：破坏时必须潜行
- 绑定方块被破坏后会失去绑定，方块消失也会被自动检测
- 虚空模式下输入路径上的漏斗每 tick 被清空，抽空间隔可配置，并带自动空闲跳过
- 多方块容器：原版箱子自动识别，模组容器可手动登记
- 三种物品可见性模式，其中包含推导出的**生存可获取**目录；配置值只是默认值，玩家可右键状态书切换自己的模式
- 可选的**自动合成**：取货不足时，用仓库里的工作台或切石机把缺少的那部分合成出来，配方可以一路往下检索
- **特殊数据物品是被管理起来的**，而不是任由它们堆积：分类里的一行代表它的收纳袋，图标画成袋里最后进来的那一堆本身，它自己的那几行被两条短短的 `最新` 黄线夹在中间——右键打开袋子本身（一个很宽敞、按页显示的已存堆列表；整盒取出和倒空袋子都在里面做）；可配置的容量一旦超出就按「最久未存入优先」销毁，还有一套过滤器可以在入库时直接扔掉不需要的——只能按物品 id 点名，没有别的开关
- 两种存储模式：服务端虚空存储，或直接以被绑定容器为存储（remote）
- 内置 `en_us`、`zh_cn`、`zh_tw` 消息，其他语言在运行时自动发现
- 通过 Mod Menu 支持 **Cloth Config**（客户端可选）
- 可作为**纯服务端**模组部署，未改动的原版客户端可进服

## 命令

*`<>` 表示必填参数，`()` 表示可选参数。所有命令都以 `/ults` 开头。*

| 命令                                       | 说明                                                                                  |
|--------------------------------------------|---------------------------------------------------------------------------------------|
| `/ults`                                    | 打开存储界面                                                                          |
| `/ults bind (备注)`                        | 绑定你正在看的容器，可带备注                                                          |
| `/ults bindarea <起点> <终点> (备注)`      | 绑定两个角点范围内的所有容器，可带备注                                                |
| `/ults delete`                             | 解除你正在看的容器的绑定                                                              |
| `/ults delete <#N 或 #N-#M>`               | 按编号解除一个绑定或一段闭区间绑定                                                    |
| `/ults list (页码)`                        | 以 `#N <维度, (x, y, z)> 备注` 列出全部绑定，有权者可直接点击删除                     |
| `/ults show`                               | 为自己显示附近被绑定容器的高亮框                                                      |
| `/ults hide`                               | 关闭自己的高亮                                                                        |
| `/ults reload`                             | 重新加载 `config/ults.json`，并重新读取服务端数据（战利品表、村民交易、配方文件、配方、创造标签页） |

`/ults` 与 `/ults list` 对所有人开放。绑定容器、区域绑定、删除绑定、开关高亮与重载配置需要**管理权限等级**（`input.permissionLevel`，原版等级 `0`-`4`，默认 `2`）；服务器控制台始终允许。`/ults list` 只会向有权删除的玩家提供点击删除。

`/ults bind` 与 `/ults delete` 的作用距离为 6 格。两者对大型容器的任意一个部件都有效，而不只是最初绑定的那一格。选段必须带井号，因此 `#3`、`#3-#5` 合法，而 `3` 会被拒绝并给出提示。

### `/ults reload` 能读到什么、读不到什么

它会把存储所依赖的一切重新读一遍，但其中两样是服务器上次加载数据包时拍下的**快照**：

| 磁盘上的改动 | `/ults reload` 能读到吗 | 原因 |
|--------------|--------------------------|------|
| 战利品表——在**文件夹**数据包中修改**或新增** | 能 | 每次重载都会从资源管理器重新列目录并打开文件 |
| `villager_trade`，或配方**文件** | 能 | 同上 |
| **取货**要用的配方，或创造标签页里的新物品 | 不能，需先执行原版 `/reload` | 配方管理器与创造模式标签页是服务器只在数据包重载时才替换的快照 |
| 一整个新数据包（文件夹或 zip），或 zip 内部的改动 | 不能，需 `/reload` 或重启 | 该数据包不在服务器的数据包列表里，或者压缩包只在启动时打开过一次 |

所以「某张战利品表开始掉落一把新剑」只需 `/ults reload` 就能让这把剑进入过滤器名单；而「教给存储一条全新配方」必须先 `/reload` 再 `/ults reload`。

## 快速上手

1. 看着一个容器（箱子、木桶、模组储物箱……）执行 `/ults bind`，也可以带备注，例如 `/ults bind "北仓库"`。
2. 往里投料。默认的 **void** 模式下，所有朝被绑定容器输送物品的已启用漏斗都会被清空，因此被绑定的容器本身不会堆满。
3. 执行 `/ults` 打开存储界面取出物品。
4. 执行 `/ults show`，48 格范围内的被绑定容器会显示描边框。

## 配置

### 配置文件位置

```
config/ults.json
```

### 示例结构

```json
{
  "general": {
    "language": "zh_cn",
    "itemVisibility": "AVAILABLE",
    "storageMode": "VOID"
  },
  "input": {
    "permissionLevel": 2,
    "maxBindings": 0,
    "drainInterval": 2,
    "multiBlockContainers": [],
    "crafting": "DISABLED",
    "allowFullInventory": false
  },
  "special": {
    "bundleSlots": 120,
    "stackRule": "COMPONENTS",
    "filterMode": "OFF",
    "filters": []
  }
}
```

文件缺失、字段缺失或枚举值未知都会回退到默认值，并在加载时把文件按规范形式重写。`general.language`、`general.itemVisibility` 与 `general.storageMode` 由 `/ults reload` 生效。`special.bundleSlots` 则在下一件物品入库或存档再次加载时立即生效，因此调小它会直接裁剪现有收纳袋，不必重启。旧版本写下的文件里是 `maxEntries` 与 `filterEquipment`，这两个字段在加载时会被直接丢弃，因为它们的含义都变了：旧上限统计的是整个分类保留多少特殊堆，而 `bundleSlots` 统计的是**一个收纳袋**装多少堆；装备也不再有开关可以自动点名。**过滤只认 `special.filters`**，所以想让刷怪塔的装备消失，就得把那些物品写进去。

## 配置详解

### 通用设置

| 字段             | 类型     | 说明                                                                                          |
|------------------|----------|-----------------------------------------------------------------------------------------------|
| `language`       | `string` | 服务端消息、命令输出与存储界面使用的语言，取内置语言之一，如 `zh_cn`。                        |
| `itemVisibility` | `enum`   | 尚未自行选择的玩家所使用的默认显示方式：`ALL`、`SURVIVAL` 或 `AVAILABLE`。              |
| `storageMode`    | `enum`   | 存储的物品存在哪里：`VOID` 或 `REMOTE`。                                                      |

### 存储设置

| 字段                    | 类型       | 说明                                                                                       |
|-------------------------|------------|--------------------------------------------------------------------------------------------|
| `permissionLevel`       | `int`      | 绑定单个容器、区域绑定、删除绑定、开关高亮与重载所需的原版权限等级 `0`-`4`，默认 `2`。       |
| `maxBindings`           | `int`      | 存储最多可绑定的容器数量，`0` 表示无上限。                                                  |
| `drainInterval`         | `int`      | 同一个被绑定容器两次抽空之间间隔多少 tick，取值 `1`-`20`，默认 `2`。输入路径上的漏斗不受它限制，每 tick 都会被清空，见下文。 |
| `multiBlockContainers`  | `string[]` | 相邻同种方块会被视为同一个大容器的方块 id，见下文。默认为空。                               |
| `crafting`              | `enum`     | 取货缺少时是否允许自动合成：`DISABLED`、`SHULKER_BOXES_ONLY` 或 `ALL`，见下文。默认禁止。     |
| `allowFullInventory`    | `bool`     | 当玩家背包装不下这次取出的全部结果时，是否仍然允许取出；放不下的部分会作为掉落物掉在脚下。默认 `false`，此时会拒绝该请求。 |

### 特殊物品设置

自带数据的物品堆——改过名字、带存储附魔、写好的书、酿好的药水、任何有损耗的东西——**按组件划分成"一种"**：同一种的两堆就是同一堆，不管游戏本身允不允许它们同格；而**没有任何标签页条目与之完全匹配**的堆叠，就是特殊分类里的一个**收纳袋**，因为分类里没有能安放它的行。下面这些设置决定"什么算同一种"、一个袋子装多少，以及哪些根本不值得保留；详见[特殊数据物品](#特殊数据物品)。

| 字段                    | 类型       | 说明                                                                                       |
|-------------------------|------------|--------------------------------------------------------------------------------------------|
| `stackRule`             | `enum`     | 同一种物品的两堆何时算同一种、可以合并成一行：`COMPONENTS`（全部组件都相同，含耐久）或 `TOOLTIP`（玩家读到的内容一样即可）。默认 `COMPONENTS`，见下文。 |
| `bundleSlots`           | `int`      | 一个收纳袋最多装多少堆。默认 `120`，正好是收纳袋界面三页（每页四十五格）。超过之后，每进来一个新的，就销毁**最久未存入**的那一个。 |
| `filterMode`            | `enum`     | 过滤器对被点名物品的处理方式：`OFF`、`KEEP_FULL_DURABILITY` 或 `FILTER_ALL`，见下文。默认 `OFF`。 |
| `filters`               | `string[]` | 过滤器要移出存储的物品 id。可省略命名空间，大小写会被归一化。**没有写进这里的物品一律保留。** 默认为空。 |

#### 两堆何时算同一种

物品与名字是两种模式共同的前提：普通剑和附魔剑是两种东西，两把不同名字的剑也是。剩下要比多少，由 `special.stackRule` 决定。

| 模式 | 含义 |
|------|------|
| `COMPONENTS`（默认） | 所有组件都必须完全一致，包括耐久——正是游戏自己判断两堆能否互换的标准。交还给玩家的永远是被存进去的那一堆本身。 |
| `TOOLTIP` | 只要玩家在它们身上读到的东西一样就算同一种，所以磨损程度不同的两把剑会合并，而附魔不同的永远不会。此时交还的是"这一类"的堆叠，而不一定是最初放进去的那一堆。 |

切换规则后需要重新读一遍存储：`/ults reload` 会按新规则重新合并已经存进去的东西，所以切到 `TOOLTIP` 就能把能合的合并掉。

**这条规则用在所有比较两堆的地方**，不只是特殊分类：什么会合并成同一行、普通分类的一行把哪些存量算作自己的——开启 `TOOLTIP` 后，仅仅更磨损的同一把剑也会被它物品的那一行计入——以及某个分类到底能不能显示某一堆。所以在 `TOOLTIP` 下，普通剑和磨损的普通剑是同一种、都属于战斗用品，而附魔剑是另一种、仍然进特殊分类。

#### 分类能装什么，收纳袋是干什么的

分类就是创造模式标签页的列表，它只能显示"与某个标签页条目属于同一种"的已存堆叠——按组件规则就是组件逐一相同，按 tooltip 规则就是两边读起来一样。其余的东西——附魔剑、命名过的镐、没人列出的药水——进入 **Special Data Items（特殊数据物品）**，由同一物品的一个收纳袋统一收着。你给的两个例子正是这条规则：普通下界合金剑在战斗用品里，附魔过的则进特殊分类。

#### 过滤器能点名什么、看不到什么

过滤判定**只按 `filters` 里写下的物品 id** 做，没有任何替你自动点名装备的开关。在信任它能把袋子保持干净之前，有两件事值得知道。

**1. 怪物身上的装备是游戏代码直接发下去的，没有任何战利品表会提到它。** 僵尸猪灵手里的长矛、猪灵身上的金甲都是在生成时交给它的；僵尸猪灵自己的战利品表只掉腐肉、金粒和金锭。所以刷怪塔的装备产物只能一件件点名——`minecraft:golden_spear`、`minecraft:golden_helmet` 等等——这正是这份名单的用途。

**2. 有 6 种物品根本没有"无组件形态"**，所以它们每一件都自带数据、永远不可能变成普通堆叠：`enchanted_book`、`potion`、`splash_potion`、`lingering_potion`、`tipped_arrow`、`suspicious_stew`。它们都不带耐久，所以任何"装备名单"都点名不到它们。**其中附魔书最要命**：村民大厅、钓鱼、开箱子都会产出，而且每种附魔与等级都各是一种堆叠。它们就是书这个物品的普通行；想清掉就写进 `filters`。

**3. 有普通形态的物品，其"带组件变体"同样只能靠 `filters` 点名**：带图案的旗帜、带乐器的高山羊角、装了鱼的桶、装饰过的陶罐、绑定磁石的指南针。

**兜底：**`special.bundleSlots` 管住一个袋子，塞满后按"最久未存入"销毁，因此单个袋子不会无限增长。现在只有"没有任何标签页条目完全匹配"的堆叠才会占一个袋子，而且分类整体没有上限，所以会大量收进自带数据堆叠（刷怪塔装备、附魔书等）的服务器，建议把 `filters` 维护好。

### 特殊数据物品

自带数据的物品堆——改过名字的剑、附魔书、写好的书、任何有损耗的东西——**每一组完全相同的组件就是一种东西**，而属于某个分类所列物品的堆叠就是**那个物品的一行**，出现在那个物品原本的分类里、紧跟该物品自己的行之后。真正还需要**收纳袋**的，是**它所属物品不在任何可见分类里**的堆叠，因为没有哪一行可以安放它。判定规则见[变体是怎么堆叠的](#变体是怎么堆叠的)。

- **一种堆叠一行。** 完全一样的两堆就是**同一堆**，和普通物品一样：让两堆不同的是它们带的东西，而不是一格能装几件——所以两把一模一样的命名剑是一堆两个，而附魔不同的两把剑是两行。
- **分类只能装它自己标签页里列出的东西**，而"列出"的判定用的就是可堆叠条件：组件规则下要求组件逐一相同，tooltip 规则下只要两边读起来一样。普通下界合金剑是战斗用品标签页的事；**附魔过的**下界合金剑不是，因为没有标签页条目读起来和它一样——所以它属于特殊物品。
- **收纳袋行。** 任何分类都显示不了的堆叠进入特殊分类，由同一物品的一个收纳袋统一收着：**Special Data Items（特殊数据物品）** 会为每一种这样的物品显示一行，并写明袋里共有多少堆、以及其中最新的一堆是什么时候进来的。行按最新在前排序，特殊分类里如此，**All Items（全部物品）** 末尾的那些行也一样。
- **这一行就是它的袋子。** 图标画的是**最后进来的那一堆本身**，内容一个不少：它带的附魔、写在它上面的 lore、它加的攻击力与攻速，颜色和数字都是游戏自己那套。名字一行写的是袋子自己的名字：`【附魔书】收纳袋`，也就是把**物品**名放进方括号、后面接上「收纳袋」。`最新` 标出下面那一段是最后入库的那一堆，最后用一条短短的黄色横线把它和袋子的信息隔开：袋里共多少堆（有筛选时改写成筛选后还剩多少堆）、最新一堆何时入库。
- **这一行只响应一个点击：右键打开袋子。** 这里没有快捷取出，因为这一行画出来的只是袋里最新的一堆，而不是整袋；里面的东西都在袋子*里面*取，那里有它自己的一行行、而且整个袋子都在眼前。左键和两种 Shift 点击在这一行上都没有作用。见[收纳袋界面](#收纳袋界面)与[全部取出](#全部取出)。
- **带上限，最久未存入的先走。** 一个袋子最多装 `special.bundleSlots` 堆（默认 120，三页）。一旦超出，入库时间最早的那些会在新堆进来时被销毁。上限计的是**堆数而不是件数**：两把不同名字的剑占两个名额，而同一把命名剑存两次只占一个。存档加载时会再执行一次上限，`/ults reload` 时也会，所以把上限调小可以直接裁剪已有袋子。
- **一套「不值得保留」的过滤器。** 被 `special.filters` 点名的物品会被移出存储。`special.filterMode` 决定下手有多重：

| 模式                   | 被过滤的特殊物品会怎样                                                     |
|------------------------|----------------------------------------------------------------------------|
| `OFF`                  | 什么都不做，名单不生效，特殊物品全部保留。这是默认值。                      |
| `KEEP_FULL_DURABILITY` | 满耐久的保留，用旧的移出存储。本身没有耐久的物品算作满耐久。                |
| `FILTER_ALL`           | 不论状态一律移出存储。                                                      |

- **两种存储模式下过滤的含义不同**，因为它们对物品的所有权不同：

| 模式     | 被过滤的物品会怎样                                                                                                              |
|----------|----------------------------------------------------------------------------------------------------------------------------------|
| `VOID`   | **销毁。** 物品本来就由存储自己保管，所以入库时直接扔掉；而且**再次应用过滤器时会清理已经存进去的**，所以改了 filter 之后虚空仓库里原本被点名的东西会被清掉，而不是只有新进来的才受影响。 |
| `REMOTE` | **只是不显示。** 物品在玩家绑定的容器里，存储无权销毁它们，因此什么都不会被移除：被过滤的堆不会出现在列表、空盒统计或取货计划里。想拿就自己去箱子里取。 |

- **只影响被装进收纳袋的堆。** 普通铁剑能和同类堆叠，因此它永远不是特殊物品，过滤器也永远碰不到它——不管它的物品 id 有没有在名单里。能堆叠多件的堆同理，它们会和同类合并成一行。过滤器只会看到那些本来就要在收纳袋里各占一条的堆。
- **被玩家改过名字的堆叠同样永远不动。** 给东西命名是有意为之——这堆东西是某人的私人物品，而不是无主的战利品——所以不论名单和模式怎么设，两种存储模式下都不会碰它。**附魔不算改名**：附魔装备照常参与过滤。因此命了名的潜影盒以及它里面的一切，都不可能被过滤器扔掉。
- `VOID` 模式下过滤发生在入库路径上（**包括被拆开的未命名潜影盒里的内容物**），并在每次应用过滤器时再做一次。被销毁的东西就是没了，没有回收站可以找回来。
- **刷怪塔的产物只能一件件写进名单**：游戏在生成怪物时把装备直接交给它，没有任何战利品表会提到，所以不存在能替你自动点名的开关——见[过滤器能点名什么、看不到什么](#过滤器能点名什么看不到什么)。
- Mod Menu 中的名单在输入时实时校验，指向本游戏中不存在的物品 id 时会拒绝保存。

### 自动合成

开启 `input.crafting` 后，只要仓库里存有配方需要的合成站，取货不足的部分会自动合成补齐；存量为 0 但能合成的物品也能取出（左键直接取一组，右键输入数量取出）：

| 模式                 | 可合成的内容                                                                   |
|----------------------|--------------------------------------------------------------------------------|
| `DISABLED`           | 什么都不合成。这是默认值。                                                      |
| `SHULKER_BOXES_ONLY` | 只合成**不带染色的潜影盒**，也就是整盒取出需要装箱的那种。                      |
| `ALL`                | 存有的合成站能做的一切物品。                                                    |

- 工作台配方需要仓库里存有**工作台**，切石机配方需要**切石机**；合成站只是被使用，永远不会被消耗。
- 可合成的物品，其物品行会显示当前能合成的数量（`可合成：N`）；开启了自动合成、但配方需要的合成站没有存货时，这一行会改成显示 `可合成：缺少合成站`，这样弄丢的工作台一眼就能看出来。存有的合成站根本做不出来的物品不会显示这一行。
- 路线会互相比较后择优：先取当前库存能产出最多的那条，再取其中操作次数最少的。因此仓库里还有切石机时，同一种楼梯会优先走操作更少的切石机路线；切石机用完了就全部回到工作台路线。
- 合成会**一路往下检索**：配方需要的中间产物如果仓库里没有，就先用仓库里的东西把它做出来，可以连续多级。例如只存了原木和潜影壳，一样能合成潜影盒：先把原木做成木板、木板做成箱子，再连箱子一起做潜影盒；开了「只允许潜影盒」时同样如此，只是最终成品仅限潜影盒。配方之间互相喂东西（例如铁块与铁锭）不会让检索陷入死循环。
- 只会合成缺少的那部分：例如需要 64 个、仓库有 60 个、配方每次产出 4 个，就只跑一次配方，另外 60 个从库存里取。批量合成多出来的中间产物（例如多余出来的木板）会**留在仓库里**，不会凭空消失。
- 结果或材料由游戏运行时决定的特殊配方（染色、烟花、旗帜与地图复制、修复等）不参与合成。
- **特殊数据物品永远不显示可合成数量。** 这样的行改为显示袋里有多少堆、以及其中最新一堆的入库时间，因为某种物品能合成多少，和某一把具体的命名剑毫无关系；右键打开袋子——合成目录根本不会被问到它们。
- 整盒取出的空盒按**普通潜影盒 → 现场合成的潜影盒 → 其他颜色的潜影盒**这个顺序拿：仓库里有普通盒就用它，不够就先合成（合成不出来多少就合成多少），仍然不够才动用其他颜色的盒子。按下确认前界面会写明「使用空潜影盒：N」和「需合成潜影盒：N」，所以用掉几个存盒、要合成几个盒子一目了然。
- 取出界面会在按下确认前列出将要合成什么。
- 在非常大的仓库上，某一行的可合成数量可能会稍晚一点才出现：一个 tick 只会花很短的时间去算这些数量，因此当前页的行会在之后一两个 tick 内陆续补齐，而不是把服务器卡住。算好之后会一直记住直到库存变化；还没轮到的行会先给出「堆能触及」的宽松答案，而不是从列表里消失。
- `/ults reload` 会重新读取服务端数据：自动合成用的配方、创造模式标签页与生存目录。哪些能热重载、哪些不能见 [`/ults reload` 能读到什么、读不到什么](#ults-reload-能读到什么读不到什么)——战利品表与村民交易它自己就能跟上，改动过的配方要先执行原版 `/reload`。

### 存储模式

| 模式     | 行为                                                                                                                                    |
|----------|-----------------------------------------------------------------------------------------------------------------------------------------|
| `VOID`   | 默认。被绑定容器是输入口：抽空循环把容器内容（以及向它输送的漏斗内容）搬进一个随存档保存的服务端存储里。                                    |
| `REMOTE` | 本身不保存物品。被绑定容器**就是**存储：区块加载时从它们身上汇总内容，取出时直接从它们里面拿。                                              |

在 `REMOTE` 模式下不会抽空任何东西：物品留在被绑定容器里，于是它们相当于能被存储界面访问的箱子。切换模式后需要 `/ults reload` 生效；两种模式下已有绑定都会保留。

#### 原样存放的东西

- **命了名的潜影盒**会连同里面的东西一起原样入库：仓库永远不会把它拆开，取出时也原封不动。没有命名的潜影盒会被拆开，内容物并入仓库，只留下空盒。
- **命了名的空潜影盒不会被当作打包材料**（即便它是空的）：整盒取出需要的空盒按「未命名的普通潜影盒 → 现场合成的潜影盒 → 其他颜色」这个顺序取，命名的盒子永远不参与。
- 组件无法被任何创造标签页条目描述的物品堆——**任何改过名字的东西**、带存储附魔的物品、写好的书等等——都会列在 **Special Data Items（特殊数据物品）** 分类里，每种物品一行，行图标画成袋里最后进来的那一堆，下面压两条写着 `最新` 的黄线；右键点开才看到袋里那些堆的本体。该分类在分类翻页区始终可达，里面没有东西时就和其他空分类一样，只在物品区中央显示那张纸。这个分类有上限也可以被过滤，见[特殊数据物品](#特殊数据物品)。

### 物品可见性模式

| 模式        | 列出的物品                                                                     |
|-------------|--------------------------------------------------------------------------------|
| `ALL`       | 所有物品与所有分类，即使什么都没存也会列出。                                    |
| `SURVIVAL`  | 生存模式能获取的一切，加上实际存有库存的物品；没有内容的分类会被隐藏。           |
| `AVAILABLE` | 仓库此刻就能交出的东西：有库存的一切，加上自动合成开启且存有合成站时当前能合成的一切；没有这类物品的分类会被隐藏。这是配置里的默认值。 |

配置里的模式只是**默认值**，不是固定值：每名玩家都可以在存储界面右键状态书切换自己的模式，选择会随该玩家的视图设置一起记住。只有当配置默认本身就是「全部显示」或该玩家拥有管理权限时，才会提供「全部显示」，普通玩家无法打开服主没有开放的视图。除再次切换外，没有「恢复默认」这个选项。

特殊物品过滤器是另一种独立的隐藏：它在所有显示方式下都生效，而在 `REMOTE` 存储模式下，正是它让被过滤的堆不出现在列表里。见[特殊数据物品](#特殊数据物品)。

#### 生存目录是怎么推导出来的

Minecraft 没有「生存可获取」标记，所以目录在存档加载时由服务器已知的一切推导（执行 `/ults reload` 时会重新推导一次）：

- 普通玩家能看到的创造模式标签页，这本身就覆盖了纯代码实现、任何数据文件都不会记录的获取途径（钓鱼、装桶、刷可疑方块、交易、附魔……）
- 每一个配方结果，既从配方管理器读取，也直接读配方文件，因此烟花、药箭、地图复制等特殊配方同样包含在内
- 每一张战利品表可能掉落的一切，包含嵌套子表与物品标签
- 村民出售的每一个物品，来自 `villager_trade` 与 `trade_set` 数据
- 没有数据文件描述、只存在于代码里的来源：所有可酿造的药水、水瓶，以及附魔台能刷出或村民能交易的每一种附魔

再减去只在创造模式出现的标签页（`op_blocks`、`spawn_eggs`）、所有 `*_spawn_egg` 物品，以及一份经过核实的清单——原版把它们放在普通标签页里但生存玩家永远得不到的方块（基岩、紫水晶母岩、强化深板岩、宝库、末地传送门框架、紫颂植物、青蛙卵、可疑的沙子与沙砾、刷怪笼、玩家头颅、石化橡木台阶，以及七种虫蚀方块，因为精准采集掉落的是它们伪装的那个方块）。

由于一切来自当前世界的标签页、数据包与配方管理器，**模组物品会被自动覆盖**。

#### 本体与类型

| 情况                                                                     | 生存视图中的行数                                                                     |
|--------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| 目录中存在不带任何组件的本体（画、烟花火箭、山羊角、不祥之瓶、旗帜）      | 只显示该本体；任何变体都不会用来代替它                                                |
| 物品只有变体，且数据知道该类型的取值（药水、附魔书、药箭）                | 每一条生存确实能产出的类型一行：所有可酿造或战利品产出的药水、书能承载的每一种附魔   |
| 物品只有变体，且数据对该类型一无所知                                      | 目录里的每一个变体，因为没有任何依据可以排除它                                        |
| 实际存有库存的物品                                                        | 永远保留自己的一行，无论处于哪种模式                                                  |

因此不可合成药水与幸运药水永远不会出现，而能酿造或能找到的药水会出现。有库存的行永远不会被合并，所以即使某本附魔书的附魔不在列表中，只要它真的存着就依然可见。

### 多方块容器

有些模组容器把一个容器拆在多个方块上，每个部件都有独立容器。把这种容器的方块 id 写进 `multiBlockContainers`，存储就会把它直接相连的同 id 方块当成一个大输入口：

```json
"multiBlockContainers": ["modid:big_chest"]
```

- id 可以省略命名空间（`chest` 会按 `minecraft:chest` 读取），大小写与首尾空格会被归一化。
- 原版箱子、陷阱箱与铜箱子无需配置即可识别；木桶永远不会合并，因为它始终是单方块。
- 登记过的方块只会与同种方块相连，向各个方向沿相邻同 id 方块蔓延（部件是否自带容器都无所谓），最多 128 个部件。
- Mod Menu 中的列表在输入时实时校验，指向本游戏中不存在的方块 id 时会拒绝保存。

### 语言

模组内置 `en_us`、`zh_cn`、`zh_tw`。其他语言会在运行时从模组内的 `assets/ultimate-storage/lang/<语言>.json` 自动发现，要求文件名匹配 `[a-z0-9][a-z0-9_-]*`，且文件里有非空的 `ults.language.name`；`en_us.json` 是必需的回退语言。缺失的键会回退到英文并在服务端日志中报告。

#### 按名称搜索

物品名称只存在于客户端：服务端发出的是翻译键，客户端用它自己设置的语言把词填进去。而搜索是客户端输入、服务端匹配，所以服务端必须知道那些词——**专用服务端自己的游戏文件里只有英文**。因此名称从四个来源读取，后者覆盖前者，并且总是用**搜索者客户端上报给服务端的语言**来回答：

| 来源 | 提供什么 |
|------|----------|
| 游戏自带文件（运行时读取） | 英文，专用服务端始终都有。 |
| `assets/ultimate-storage/itemnames/<语言>.json`（打包时烘焙） | 游戏自己给物品的名称，覆盖**模组内置的每一种语言**（目前是 `en_us`、`zh_cn`、`zh_tw`）。 |
| 每个已加载模组自带的语言文件 | 各模组自己的物品名，模组带哪些语言就有哪些语言。 |
| `config/ults/lang/<语言>.json` | 服主自己放进去的东西：整套别的语言，或者自己的修正。它的优先级最高。 |

- 读某个语言时永远先铺一层英文，和客户端一样，所以某个语言缺的词会回退到英文，而不是消失。
- **搜索只读你当前选中的那个分类**：选中红石方块再搜 `ore`，匹配的就只会是红石方块；过滤界面上的数字就是那个分类会显示的行数。
- **收纳袋是按袋里的东西被搜到的。** 收纳袋行只显示其中一堆，代表的却是整袋，所以在 **Special Data Items（特殊数据物品）** 里，只要袋里任何一堆能匹配，这一行就会留下；打开袋子后也只铺出这些匹配的堆，其余的都藏起来。因此在特殊分类搜 `锋利`，会找到那袋附魔书，打开就只看到携带它的那几本。有筛选时这一行只写一个数字：`袋中符合筛选：1`，也就是打开袋子会铺出来的数量——它直接问的就是袋子界面自己的那套代码，两边不可能对不上；没有筛选时才写 `袋中：3`。
- **堆叠身上携带的内容也会被匹配**，既用玩家自己的语言，也用背后的 id：`锋利` 和 `sharpness` 都能找到携带该附魔的附魔书，药水按效果找、旗帜按图案找——凡是 tooltip 上写着的都算，因为匹配的就是它。
- **物品 ID 始终也会被匹配**（`diamond`、`minecraft:diamond`），这就是即使服务端对这名玩家没有任何该语言数据、搜索依然可用的原因。
- 匹配的是物品真正带着的名字：自定义名称按你写的搜；由别的名字拼出来的名字（药水、刷怪蛋之类）会先拼好再匹配。
- 这些表是从 Loom 已经下载好的 Minecraft 资源里烘焙的，所以会自己跟着 `gradle.properties` 里的版本走；而**要烘焙哪些语言，是看模组自己带了哪些语言文件**，因此往 `assets/ultimate-storage/lang` 里放一个 `ja_jp.json`，日文物品名就会一起烘焙进去（英文取自游戏 jar，而不是资源索引）。游戏没有对应语言时会在构建日志里说明并跳过；构建机器上连这些文件都没有时，就只保留游戏自带的英文名，搜索照常可用。`/ults reload` 会连同 `config/ults/lang` 一起重新读取。

## 容器输入

### 绑定

看着容器执行 `/ults bind`；备注是最多 64 个字符的文本，不能包含控制字符与格式符号 `§`。同一个方块重复绑定会被拒绝；达到上限（`input.maxBindings`，`0` 表示无上限）时会给出明确提示，而区域绑定会尽量绑到上限为止。

### 区域绑定

`/ults bindarea <起点> <终点>` 绑定两个角点之间的所有容器。只扫描已加载的区块，选区每条轴最多跨 128 个区块，已经绑定过的容器会保留原有绑定与备注。返回消息区分三种情况：全部为新绑定、部分已绑定、达到上限后其余被跳过。

### 抽空（仅 void 模式）

| 行为            | 说明                                                                                                                            |
|-----------------|---------------------------------------------------------------------------------------------------------------------------------|
| 抽空间隔        | 每个绑定每 `drainInterval` tick 被访问一次，并摊到不同 tick 上，避免大型仓库在同一 tick 被集中处理。                             |
| 空闲跳过        | 一段时间没有产出任何物品的绑定会被降低访问频率：有漏斗路径时每 2 次访问一次，没有时每 8 次访问一次。                            |
| 清空漏斗        | 朝被绑定容器（或该路径上另一个漏斗）输送的已启用漏斗会被清空并重置传输冷却；整条链路最多向上追溯 8 个漏斗。                      |
| 漏斗吸力        | 在 `VOID` 模式下，输入路径上的漏斗**每 tick** 都会被清空，而不是只按抽空节奏处理，因此被绑定容器能以漏斗推送的最快速度吸入物品：每个漏斗约 1 个/tick，而不是原版的 8 tick 一个。 |
| 未加载区块      | 未加载区块中的绑定会被跳过，内容保留到区块再次加载。                                                                            |
| 方块消失        | 方块已消失（空气）的绑定会被移除并通知玩家。                                                                                    |

### 解除绑定

`/ults delete` 解除你正在看的容器。`/ults delete #3` 与 `/ults delete #5-#8` 按编号解除；`/ults list` 会显示编号，并向有权删除的玩家提供点击删除。潜行破坏被绑定的方块同样会解除绑定。

## 存储界面

`/ults` 打开一个 9×6 的界面。最左列是分类翻页区：一个向上箭头、四个分类按钮、一个向下箭头。第二列是分隔条，剩余 5×7 区域每页最多显示 35 行物品。该区域第一行依次是上一页箭头、状态书与下一页箭头；只剩一页时，这两个物品翻页箭头**完全不出现**（无处可翻），而分类上下箭头始终显示。列表一行都没有时，物品区中央会显示一张纸说明。

- **分类**来自世界加载时发现的创造模式标签页，外加 **All Items（全部物品）**——其它所有分类的汇总，收纳袋行排在最后——以及 **Special Data Items（特殊数据物品）**，它只装"没有任何标签页条目与之完全匹配"的已存堆叠。在当前可见性模式下没有任何可列内容的分类会被隐藏，而 **All Items** 与 **Special Data Items** 始终可达，即使里面一件东西都没有。列表一行都没有时，物品区中央会显示一张纸说明。收纳袋行代表同一种物品的全部变体，按其中最新一堆的入库时间排序，图标画的正是那一堆：名字一行写的是袋子自己的名字 `【物品名】收纳袋`（按物品而不是按最新那一堆的名字），下面 `最新` 标出最后入库的那一堆，再由一条短黄线收尾；特殊分类与 **All Items** 末尾追加的那些行都是如此。有筛选时，它写的是筛选后留下的堆数，而不是袋里总数。
- **状态书**显示当前分类、分类页、物品页、列出与存有的物品种类数、有多少个收纳袋以及最满的那个装了多少、当前过滤条件以及当前显示方式；左键它打开**过滤界面**，可以输入物品的名称、ID 或它身上的东西、应用或清除；右键它切换这名玩家的显示方式。**搜索只读你当前选中的那个分类**——比如选中红石方块再搜，匹配的就是红石方块里的东西——而且按物品名称、物品 ID 和**堆叠身上携带的内容**回答，所以 `锋利` 或 `sharpness` 都能搜到那本附魔书，在特殊分类里也能搜到装着它的那袋。输入内容后才会显示匹配数字，它就是那个分类将会显示的行数，所以数字和列表永远不会打架。最满的袋子装满时会变红，那正是新的特殊堆开始销毁最旧一堆的时候。见[按名称搜索](#按名称搜索)。
- **物品行**显示存有数量，达到一盒后会附带换算的潜影盒数量，并写明各按键做什么：**左键直接取走一组**——能装多少就取多少，不足一组就全部取走；开启合成且存有合成站时，缺的部分会现场合成；**右键询问数量**，打开**取出界面**——只要这一行有东西可拿，右键就一定打开它，哪怕只有一件：取多少是玩家自己的回答，界面会先把存量说清楚，再等你确认。之后 Shift+左键**整盒取出**，Shift+右键**全部取出**——它会先问你确认，并给你"含合成 / 不含合成"两个选择。**收纳袋行是例外**：它只响应一个点击，右键打开**收纳袋**，因为它画出来的那一堆只是袋里最新的一堆，而不是整袋。见[特殊数据物品](#特殊数据物品)、[收纳袋界面](#收纳袋界面)与[全部取出](#全部取出)。
- **提示不会承诺存储做不到的事。** 一行会把它响应的每种点击都列出来，做不到的那条直接不显示、而不是灰着摆在那里。左键那行永远写明它会取走**多少**——`左键：取走 64 个。`，不足一组时就写剩下多少。`Shift+左键：整盒取出。` 这行在整盒根本拿不出来时**完全不显示**（该物品不够一盒、没有可用的空盒也合不出空盒、或者这东西本身就是潜影盒），此时这一行只剩"全部取出"。**收纳袋行只列出它响应的那一行**——`右键：打开收纳袋。`——完全不提左键与 Shift，因为那两种在它身上都不起作用。如果点击时存量才发生变化，界面依然照常响应，而且**按点击那一刻的库存**结算：真的有多少就取多少，取完这一行会带着新的数字重画。整盒装不满时会给出红色提示 `存量和可合成量都不够装满一盒。`，并且什么都不会取走。
- **提示是一次把每种点击都列出来，而不是跟随 Shift 键变化的**——这是游戏本身的限制，不是取舍：打开任何界面时客户端会释放所有按键并停止跟踪按键状态，所以它上报给服务端的输入永远是"没按 Shift"，无论玩家手上按着什么。服务端因此无法在按下 Shift 的瞬间重画提示，只好把这一行响应的点击一次说全。Shift 点击本身照常可用，因为按键状态是随点击本身一起送到的。
- 无论左右键，拿到的东西都按取出的规则进背包：放不下时会拒绝并提示，开了 `input.allowFullInventory` 则掉落在脚下。
- 选中的分类、分类页、物品页、过滤条件与显示方式按玩家保存在存档数据中，因此每个人回到自己的视图——**取出之后也不会丢失**：界面会回到原来的位置。
- 点击会播放一段只有点击者能听到的短音效：打开界面、翻页、选择分类、切换模式是轻响，应用筛选与确认取出是更明亮的拾取音；各种「取消并返回」不发音效。
- 已打开的界面会在库存数量变化时自动刷新，"可合成"的数字也一样。在每秒都有新东西入库的仓库上，这些答案允许有一瞬间的延迟——每 tick 都把整张合成图重算一遍是搜索不会做的事——但**这种延迟绝不会一直挂在那里**：界面会持续重画，直到数字重新对上库存；而**点击**一秒都不等，它问的是点击那一刻的库存，而不是这一行当初画出来时的数字。

### 取出界面

**左键点一行会直接取走一组**；这个界面是**右键**打开的，只要这一行有东西可拿就会打开，只有一件也一样：取多少只有玩家自己能回答，没有小到可以跳过询问的数量。它会在铁砧样式输入框上方询问数量，并提供两种模式：

| 模式     | 含义                                                                        |
|----------|-----------------------------------------------------------------------------|
| 散装模式 | 按输入数量取出散装物品。                                                    |
| 整盒模式 | 把输入数量当作潜影盒数量，消耗同样数量的空潜影盒，每盒装满 27 组物品。       |

铁砧左侧槽位是取消按钮（返回存储界面），中间槽位切换两种模式。中间槽位同时会写清这次取出需要什么：存有数量、输入数量、将要合成多少物品与多少个盒子，整盒模式下还有可用空潜影盒的数量以及这次会用掉几个。取消那句提示是左侧物品的**第一行 tooltip**而不是它的名字——因为原版客户端会把该槽位物品的名字直接抄进输入框，写成名字会让输入框预填整句话、之后你打的字还会追加在后面。当请求无法完成时，确认按钮不可用并会说明原因：数量不是正整数、想把潜影盒装进潜影盒、结果超过 36 组、存有物品或空潜影盒不足、背包放不下完整结果。确认时会重新校验并原子扣除，因此两名玩家无法取走同一批物品。开启 `input.allowFullInventory` 后，背包装不下完整结果不再阻止取出：确认按钮会用红字写明这一点，而放不下的部分会作为掉落物掉在脚下。

过滤界面使用同样的三个槽位：取消、清除筛选、应用输入内容。

### 收纳袋界面

收纳袋要用**右键点行**才会打开，而这是这一行唯一会做的事：它不响应左键，也不响应任何 Shift 点击，因为它画出来的那一堆只是袋里最新的一堆，而不是整袋。所有东西都在袋子*里面*取，盒是在袋子里打的，倒空也是在袋子里倒的。这个界面是一个很宽敞的 9×6 界面，上面五行**就是仓库里存着的那些堆本身**，一堆一格、最新在前：**每页四十五格**，所以默认容量装满时是三页。

- **每格只显示一件，存量写在 lore 里**，不管那一堆实际有多少：袋子读起来就是"每格一件东西"（那一行会写 `存量：64`），而不是一排数字；不可堆叠的东西也一样。
- **袋内每一堆的行为和存储界面的物品行完全一样**，因为它就是同一件事：左键取一组、右键选数量、Shift+左键整盒、Shift+右键把这一堆全部取出。**收纳袋里没有另一套"按类取出"的规则。** 提示也是同一套智能提示：这一堆不足一组时左键那行会写明真正能取走多少个，整盒拿不出来时整盒那行不显示。
- **收纳袋行本身画成最后进来的那一堆，内容一个不少。** 悬停读到的是那一堆真正是什么样——它的名字、它带的附魔、写在它上面的 lore、它加的攻击力与攻速——颜色和数字都是游戏自己那套，因为这些就是游戏画在那一堆上的那几行。有两点让它读起来和玩家熟悉的悬停一模一样：

  ```
  【附魔书】收纳袋
  ───── 最新 ─────
  附魔书
  锋利 V
  ──────────────
  袋中符合筛选：1
  最近存入：2026-09-28 22:26
  右键：打开收纳袋。
  ```

  - **标题写的是袋子，不是那一堆。** 它是袋里**所有堆共同的那件物品**，放进方括号再接上「收纳袋」：一袋名字各不相同的下界合金剑，就是「下界合金剑的袋子」，不管最新的那把叫什么。这一行交给客户端去翻译——行里塞的是一个**物品名组件**而不是写死的字，所以中文客户端读到 `【附魔书】收纳袋`，英文客户端读到 `[Enchanted Book] Bag`。
  - **下面那几行是这一堆自己的，而且是按「读的人」算出来的。** 游戏算武器的攻击力与攻速时会去问玩家自己的基础值，所以同一个堆在拿不到玩家时只能印出它带的修正值 `-2.4 攻击速度`，而客户端印的是 `1.6 攻击速度`；这一行把玩家一起交给游戏，所以它印出来的和悬停印出来的一致。这中间不加任何行、也不删任何行：那一堆自己的行里本来有空行就保留，本来连着的就照样连着，所以这一段读起来和悬停一模一样。
- **标题那一行的颜色由游戏决定，所以图标不是原封不动的那一堆。** 游戏会按**稀有度**给名字行上色、并抹掉上面设的样式，而且**附魔过的物品稀有度会被自动提高一级**——所以「黄色」不是染上去的，而是换成颜色就是黄色的那一档稀有度，同时把图标身上的附魔组件摘掉（那几行本来就由上面这个块自己画），它原来该有的附魔光效用 `ENCHANTMENT_GLINT_OVERRIDE` 单独补回来，因此图标看起来一点都不变，右键拿到的仍然是仓库里那一堆本体。
- **找到这个袋子的筛选，进了袋子依然生效。** 在特殊分类里打开一个袋子，只铺出筛选留下的那些堆、其余的都藏起来，所以靠 `锋利` 搜到的袋子打开后就只看到携带它的那几本书；最下面那本书会写明当前的筛选内容，开着筛选时会带附魔光效。有筛选时上面那一行只写一个数字——**筛选后留下的堆数**，也就是打开袋子会铺出来的数量，因为看着筛选结果的玩家问的就是这个；没有筛选时才写袋里总数。两个数字都直接来自袋子界面自己的那套代码。
- 无论哪条路径，拿到的东西都按取出的规则进背包：放不下时拒绝并提示，开了 `input.allowFullInventory` 则掉落在脚下。仓库立刻跟着变：拿到的那些从那一刻起就不再是存着的东西。
- 最下面一行是返回存储的按钮、**多于一页时分列在状态书两侧的翻页箭头**，以及那本状态书：它写明这个袋子存了多少堆、当前第几页、正在用哪个筛选；**右键点它就是申请把整个袋子全部取出**（里面每一堆都按原样离开），倒空袋子本来就应该在袋子里面做。袋子被取空后只显示一张纸——开着筛选时则是一张写着"袋中没有符合筛选的物品"的纸——而它背后存储界面上的那一行也会随之消失。
- 收纳袋会在库存变化时自动刷新，和其它界面一样：新入库的排到最前，被过滤器销毁的消失，你正在看的页也会保留。
- `REMOTE` 模式下收纳袋只能往外拿、不能往里放：离开袋子的东西是从它来源的绑定容器里取出来的；如果那个容器中途被掏空了，界面就如实显示现在的样子。

### 全部取出

Shift+右键是"把这个东西清空"的意思，所以它是一个提问而不是命令：**一行里居中放三个按钮**——第 3 格返回、第 5 格模式、第 7 格确定。它用的是普通容器而不是数量界面那个铁砧界面，因为这里根本没有东西可输入：一个天生没法打字的界面，胜过一个必须想办法把输入框清空的界面。**返回用的就是铁砧界面那颗红色染料**，标签写在第一行 tooltip 上，所以在哪儿离开界面看起来都一样。

| 模式 | 会取出什么 |
|------|------------|
| 物品模式 | 只取存着的全部，不合成。没有存量时不提供。 |
| 工作台模式 | 存着的全部，加上配方与已存合成站现在能补上的部分。当前合不出任何东西时不提供。 |

中间那格用来切换两种模式，并写明每种模式意味着什么：存量多少、当前能合成多少、这一模式会取出多少。**在你点右边那格确定之前，什么都不会发生。**

- 在收纳袋界面里，**右键点状态书**就是申请"全部取出"：那指的是**整个袋子**，里面每一堆都按它本来的样子离开。袋子里装的是别人放进去的东西，没有配方能造出来，所以那里不提供"含合成"。
- 取出的东西按取出的规则交付，唯一区别是**放不下的直接掉在地上**而不是退回仓库：既然玩家要的是"全部"，那给一半不算数。

## 高亮与保护

`/ults show` 与 `/ults hide` 只切换**你自己的**高亮、需要与绑定/删除相同的权限，不影响其他玩家。48 格范围内最多 16 个被绑定容器会显示贴合方块的发光描边，每秒刷新两次。当你看着一个被绑定容器时，动作栏会显示它的绑定，例如 `绑定 #3（北仓库）`。

被绑定的方块受保护：破坏时必须潜行。普通破坏会被取消并回复 `该容器已被存储绑定：需潜行（Shift）才能破坏。`（每位玩家最多每 2 秒提示一次）。潜行破坏会解除绑定并告知解除了哪一个；因其他原因消失的绑定方块也会自动失去绑定（提示 `绑定 #N（备注：…）的方块已被破坏，已自动移除该绑定。`）。

## 存档数据

绑定与按玩家的界面状态保存在主世界的 `SavedData` 中，因此**每个存档拥有自己的存储**，复制存档也会复制存储。模组不会把任何内容写进容器或玩家的 NBT。在 `VOID` 模式下，存储的物品就在同一份存档数据里；在 `REMOTE` 模式下，物品留在原地，也就是被绑定的容器里。每一个存进去的堆都会记住它的入库时间——特殊分类的列表、显示、排序与裁剪都靠它；在加入这个时间戳之前写下的存档照样能读取，只是其中的堆会被当作最旧的一批。收纳袋行画出来的那个 bundle 是当场构造的，只存在于那一行里：模组永远不会把 bundle 物品写进世界或玩家的背包。`REMOTE` 模式下，容器本身分不清两把一模一样的命名剑，因此收纳袋装的是它在容器里找到的各种组件组合，一种组合一条内容。

## Cloth Config 支持

客户端安装 **Cloth Config API** 与 **Mod Menu** 后，所有设置都能在游戏内修改。界面分为 **General（通用）**、**Storage（存储）**、**Special items（特殊物品）** 三个页签，每个页签在 **Overview（总览）** 页签里各有一份镜像。每个条目的名称都很短，每段 tooltip 都按同一套排版：一行摘要、空行、详细说明，需要举例时再补一条例子，因此不必读一整段话就能看懂一个设置。该界面只编辑此客户端的本地 `config/ults.json`，无法修改远程专用服务器。保存时会校验并以 UTF-8 原子写入 JSON；指向本游戏中不存在方块或物品的 id 会在输入时标红并阻止保存。物品过滤名单用的是和多方块容器名单同一套带编号、带校验的列表控件。在集成服务器上执行 `/ults reload` 让文件生效。

## 构建

```bash
./gradlew build      # 构建 build/libs/ultimate-storage-<版本>.jar
./gradlew test       # 运行单元测试
./gradlew runServer  # 启动开发用服务器
```

需要 Java 25。

`build` 还会把游戏自带的物品名烘焙进 jar，**覆盖模组内置的每一种语言**——目前是 `en_us`、`zh_cn`、`zh_tw`，这一组直接从 `assets/ultimate-storage/lang` 下的文件读出来（任务 `generateItemNames`，输出到 `build/generated/ultsItemNames`），这样就能用玩家客户端渲染物品时所用的语言来回答搜索。词条取自 Loom 已经下载好的 Minecraft 资源，资源索引里没有的语言（英文就是如此）则取自 Loom 缓存里的游戏 jar；构建机器上都没有时只保留游戏自带的英文名。见[按名称搜索](#按名称搜索)。
